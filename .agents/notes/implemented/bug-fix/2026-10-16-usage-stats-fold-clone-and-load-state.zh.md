# Agent Note: 用量统计按需克隆日期并把加载态显示为加载中

Status: implemented

[English](2026-10-16-usage-stats-fold-clone-and-load-state.md) | 中文

## 问题

对用量插件的一次审计暴露出两个问题。

**每次折叠都克隆整个聚合。** `foldAll` 用 `restoreDay(structuredClone(persistDay(day)))` 为每一个已提交的日期构造工作状态。`persistDay`/`restoreDay` 本用于在内存中的 `Map` 形态与 JSON 检查点形态之间转换，所以把一次克隆绕经它们等于把同一份数据转换了两遍，还在 `structuredClone` 已经做过的复制之上重建了每天的 24 个小时对象。按 370 天的协议上限实测，无论有无变动，每次折叠约耗 29 ms。

**指标卡在加载时读起来像已测得的零。** `loading` 即 `!hasValue`，图表分支在它为真时已会渲染加载文案，四张指标卡却没有：它们在已被清空的桶上渲染 `formatFull(totals.input)`，于是冷启动——`value: null`、无检查点、本机实测回填 19–28 秒——会出现四张卡显示 `0`、旁边图表写着「加载中」的画面。而 `0` 与页面用来表示「已测得的空窗口」的文本完全相同，两种状态因此无法区分。切换窗口、日期或模型有同样的效果。

## 决策

**首次写入某天时才克隆它。** 折叠的 `days` Map 现在以已提交 Map 的浅拷贝起步，`day()` 在本次折叠第一次触碰到某一天时克隆它。`day()` 是 `state.days` 的唯一写入方，因此写时复制按构造即是完备的：本次折叠未写过的日期，仍是读者经由 `committed` 看到的那个对象，而折叠抛出时已提交的聚合分毫不动。浅拷贝 Map 约 0.1 ms，因此常见情形——只有跨越持久化屏障的会话会被访问，什么都没变的折叠不会触碰任何日期——完全不再承担按日的成本。被触碰的日期约 0.027 ms，而经往返转换是 0.043 ms。

**首次响应返回前卡片显示破折号。** `loading` 期间四张卡各渲染 `—` 而非数字，两条副标一并抑制，因为分母未知时的命中率没有意义。这与图表既有的加载分支一致，并让 `0` 只表示「已测得的空窗口」。切换窗口、日期或模型仍会丢弃上一批桶——上一窗口的数字不是新窗口的——因此切换读起来是加载中，而不是一个虚假的总量。

## 备选方案

**修剪超出 `[1, 370]` 天窗口的日期。** 拒绝。尾部窗口到不了它们，但日期选择器的「上个月」没有下界，且 host 有意地回答任意日期，对不存在的日期返回零桶而非报错。因此修剪会把一个真实的过去日期变成一次静默的零读数。按实测每天 2.4 KiB，到上限时检查点约 900 KiB，尚不值得为此付出。

**稀疏小时桶。** 真实检查点中每天 24 个小时槽位有 89% 没有用量，只编码非空的那些可让小时部分小约 68%。暂时拒绝：它改变了存储形态，因此需要提升域版本，而提升版本会让两种后端在打开时以 `version-mismatch` 拒绝陈旧单元——JSON 后端保留文件而不备份——在单元被清空前让所有注入 `storageDomain` 的插件停在 pending。等检查点真的成为实际成本时再议。

**切换期间像刷新路径那样保留上一窗口的桶。** 拒绝。刷新路径重读的是**同一个**窗口，其桶仍是答案；而切换是在问一个不同的问题，在新窗口的标签下显示旧窗口的总量是一种错误，而加载占位不是。

**渲染骨架屏或微光效果而非破折号。** 拒绝，那会为仅持续一次请求的状态引入更多机制；破折号复用已有的排版，无需新样式。

**仅在折叠将会改变结果时才急切克隆。** 拒绝：折叠是否会改变结果只有在它跑完之后才知道，而按日克隆无需预测就得到了同样的结果。

## 后果

- 没有变动的折叠现在只付一次 `Map` 拷贝的代价。冷折叠的性质不变；节省量与存在多少天成正比，而与访问了多少天无关。
- 折叠的工作状态在写入前与已提交聚合共享日期对象，因此在折叠运行期间遍历 `committed` 的读者看到的每天总量仍前后一致，与此前相同。
- `persistDay`/`restoreDay` 仍用于两处真正需要形态转换的地方：从检查点播种，以及写回检查点。
- 页面在首次响应前不再显示 `0`，切换窗口也不会再把卡片清成一个虚假总量。
- README 记录了两个暂缓的选项——修剪与稀疏小时桶——连同实测数字与各自暂缓的原因，下一个读者无需重新发现版本提升的代价。

## 测试

移除按日克隆会让 `does not expose partial totals or advance cursors when checkpoint saving fails` 失败，因为进行中的折叠会改动缓存读取正在使用的那个已提交日期。移除破折号会让 `shows a placeholder rather than a measured zero before the first response` 失败。让 `setDays` 保留上一批桶会让 `reports a window switch as loading rather than a measured zero` 失败。每一项都在代码还原前经变异确认。

`tsc -b tsconfig.client.json tsconfig.node.json` 干净，包内测试 83 条全部通过。
